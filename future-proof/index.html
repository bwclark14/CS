How computers think and talk

Every prediction about the future of technology depends on two things: how fast computers can process data, and how fast they can share it. Here you go inside a processor, race through the memory hierarchy, and follow a message across the internet.

1.2 · THE MEMORY HIERARCHY

If one tick of the processor took one second…

A modern processor ticks about three billion times a second. That’s too fast to imagine, so let’s slow everything down: pretend one tick lasts a whole second. Now tap each kind of storage to see how long the processor would wait for data.

Why have a hierarchy?

Fast memory is expensive and small. Slow storage is cheap and huge. So computers keep what they need right now close to the processor (registers and cache), what they’re working on in RAM, and everything else in secondary storage. RAM is volatile: switch off and it forgets. SSDs and hard disks keep data without power.

Link to the future

A smart speaker sends your voice to a data centre because the AI model is too big for the speaker. On the scale above, that trip takes years. That delay is why companies now try to run AI on the device (called edge AI). Keep this in mind for Part 4.

1.4 · THEN VS NOW

How long would it take?

By 1983 a few people in the UK could already bank and shop from home on Prestel, using a modem and their TV. So why didn’t online shopping take off until the 2000s? Pick a file and compare download times.

Choose a file

Bits and bytes

Connection speeds are measured in bits per second. File sizes are measured in bytes. 1 byte = 8 bits. 1 MB = 1,000,000 bytes. So time = (file size in bytes × 8) ÷ speed in bits per second.

Think about it. Which of these would make watching films online impossible, even if everyone wanted to? What does this tell you about why a prediction can be right about what people want, but wrong about when?

2.5 · CASE FILE

The time capsule nobody could open

In 1986 the BBC made a digital “Domesday Book” to mark 900 years since the original. It should have been a gift to the future. Within about fifteen years, almost nobody could read it.

1086The original Domesday Book records England. It is written on parchment and can still be read today.
1984–86Schoolchildren and members of the public across the UK write about their local area. Around a million people take part. Acorn, Philips, Logica and the BBC build the system.
1986It is published on special laser discs that need a Philips player connected to a BBC Master computer.
~2000The players and computers are obsolete. Very few still work and the discs are starting to decay. Paper from 1086 is easier to read than discs from 1986.
2002–2010Volunteers and researchers rescue the data, repair a working system and copy everything. An online version follows in 2010.

Why this matters for your time capsule

In Part 5 you will seal a prediction to open in five years. Digital files only survive if something can still read them. That needs the file format, the software, the storage and, if you encrypt it, the key.

Discuss

  • Which file format would you trust to still open in 2031: a .txt file, a .docx, a phone video, or a page on a website? Why?
  • Who should be responsible for keeping digital things readable: the person who made them, the company, or libraries and museums?
  • Name something you’ve made that you might not be able to open in five years.

Digital obsolescence: when data still exists, but the hardware or software needed to read it doesn’t.

3.1 · HOW A SMART DEVICE WORKS

Sense, decide, send, act

Every smart device, from a doorbell to a fitness tracker, does the same four jobs. The micro:bit can do all four.

    4.2 · A TASTE OF QUANTUM
    
Bit or qubit?

    
An ordinary bit is always 0 or 1, like a coin lying flat. A qubit can be in a superposition: more like a spinning coin. While it spins, it isn’t heads or tails yet. When you measure it, it lands, and you only ever see 0 or 1.

So why is quantum computing powerful?

      
Two ordinary bits hold one of 4 patterns at a time (00, 01, 10, 11). Two qubits can be in a superposition of all 4. Every extra qubit doubles it:

      
QubitsPatterns held at once

      
Clever quantum programs make the wrong answers cancel out and the right answer more likely when you measure. That only works for some problems, like simulating molecules for new medicines. It won’t make your games faster.

      
The catch: qubits are fragile. Heat, vibration or stray signals make them collapse early, so many machines are kept colder than outer space. That’s the hardware bottleneck today.

    How does the lock work?
    
If you add a passphrase, your prediction is encrypted with AES, the same kind of encryption used by banks and messaging apps. The passphrase is turned into a key; without it, the file is just scrambled numbers. The file also stores an “open after” date, but that is only a label: anyone with the passphrase could open it early. Real delayed-release systems need a trusted keeper, which is your teacher’s job. And if the passphrase is lost, nobody can ever open it. That’s exactly the Domesday problem again.

How the simulations work

        
Fetch–decode–execute: a 16-location accumulator machine with an LMC-style instruction set (LDA, STA, ADD, SUB, INP, OUT, BRA, BRZ, BRP, HLT, DAT). Each Step shows one phase. INP reads the temperature slider. Values are kept between −999 and 999.

        
Memory hierarchy: latencies of about 0.3 ns (register), 1 ns (cache), 100 ns (RAM), 100 µs (SSD), 10 ms (hard disk) and 60 ms (cloud round trip), scaled so one 0.3 ns clock tick = 1 second. Animation length is on a log scale.

        
Packets: six packets choose randomly between the working routes through four routers, so they arrive out of order and are sorted by sequence number. Breaking a router forces traffic onto the remaining paths.

        
Bandwidth: time = bytes × 8 ÷ bits per second, with no protocol overhead. Real downloads are a little slower.

        
micro:bit simulator: the sensor checks its reading every half-second and sends a message when the rule is met (light and temperature) or on each shake (steps). Messages are only received on a matching radio group. The “nosy neighbour” is always on group 1. Scrambling is a simple Caesar shift on letters, to show the idea of a shared key; it is not real security. The generated code uses the standard MakeCode and MicroPython radio APIs.

        
Qubit: each measurement returns 1 with the chosen probability. It models measurement only, not interference or entanglement.
